# Flow Dock 下一阶段 TODO（组件指纹与相似度）

## 目标
- 为页面中框选到的组件生成稳定指纹
- 支持跨页面/跨时间的相似度比对
- 控制性能开销，保证可回归验证

## 里程碑

### M1：采集链路稳定化（先做）
- [ ] 在一次采样中完成 `bbox + DOM 绑定`（避免二次采样漂移）
- [ ] 扩展检测结果结构，补充字段：`domPath`、`tag`、`role`、`textHash`、`classTokens`
- [ ] 记录环境上下文：`url`、`scrollX/scrollY`、`viewport`、`dpr`、`ts`
- [ ] 增加去重策略（同位置+同结构）并保留 `runId`
- [ ] 增加失败兜底：DOM 不可绑定时保留纯 bbox 记录

**验收标准**
- [ ] 同一页面重复执行 3 次，关键组件绑定成功率 >= 90%
- [ ] 无阻塞主线程的明显卡顿（单次分析耗时可控）

---

### M2：轻指纹（在线）
- [ ] 定义轻指纹字段（建议）
  - [ ] 几何特征：归一化 `x/y/width/height`、面积比、长宽比
  - [ ] 结构特征：`tag`、`role`、层级深度、兄弟序号分桶
  - [ ] 内容特征：文本长度分桶、`textHash`、属性摘要（`aria-*` / `data-*`）
- [ ] 实现轻指纹生成函数（可在采集阶段同步计算）
- [ ] 实现轻相似度打分（加权：几何+结构+内容）
- [ ] 增加阈值策略：`high` / `medium` / `low`

**验收标准**
- [ ] 人工抽样 50 对组件，Top-1 命中率达到预期（先定基线）
- [ ] 轻指纹生成耗时在可接受范围（每批次线性增长）

---

### M3：重指纹（离线/异步）
- [ ] 设计重指纹任务队列（避免阻塞主流程）
- [ ] 接入可选特征：局部截图特征 / embedding / OCR 增强
- [ ] 建立重排流程：轻指纹召回 -> 重指纹复排
- [ ] 落库存储重指纹版本号，支持升级回填

**验收标准**
- [ ] 与仅轻指纹相比，误匹配率显著下降
- [ ] 异步任务失败可重试，不影响主流程可用性

---

### M4：可观测性与回归
- [ ] 增加分析统计：候选数、保留数、绑定成功率、各阶段耗时
- [ ] 增加日志采样与错误分类（脚本注入失败、DOM 变化、权限问题）
- [ ] 固化回归数据集（典型页面 + 预期匹配结果）
- [ ] 建立回归脚本与阈值报警

**验收标准**
- [ ] 每次改动可自动输出质量对比报告
- [ ] 回归失败可快速定位到具体阶段（采集/指纹/匹配）

## 风险与应对
- 动态页面重排导致绑定漂移
  - 应对：单次采样完成绑定，保存上下文并使用近似匹配兜底
- 噪声节点过多影响相似度
  - 应对：高召回 + 强过滤，不追求“全标签覆盖”
- 性能压力
  - 应对：轻重分层、同步轻计算 + 异步重计算
